🚀 Project Overview

This project simulates a small business network connected through an ISP environment using Cisco Packet Tracer. The purpose was to demonstrate both network implementation and practical troubleshooting.

🎯 Project Goal

Build a functional network environment that supports multiple departments while providing logical segmentation, routing, automatic addressing, dynamic routing, and simulated Internet connectivity.

The project also intentionally introduces network failures so that they can be diagnosed using a structured troubleshooting methodology rather than guesswork.

💼 Business Impact

⚡ Reduced Downtime

Structured troubleshooting helps identify problems faster and reduces unnecessary service interruption.

🔍 Less Guesswork

A layer-by-layer diagnostic process makes troubleshooting more consistent and repeatable.

🌐 Reliable Connectivity

Routing, VLANs, DHCP, OSPF, and NAT work together to provide reliable end-to-end connectivity.

🧠 Operational Thinking

The project focuses on restoring services and verifying the result, not simply applying configurations.

⚙️ Technologies & Concepts

🔀 VLAN Segmentation

Departments are separated using VLANs to create logical broadcast domains and improve network organization.

🔄 Inter-VLAN Routing

Router-on-a-Stick is used to allow communication between different VLANs through router subinterfaces.

📡 DHCP

DHCP provides automatic IP addressing, subnet masks, gateways, and other client configuration information.

🌐 OSPF

OSPF provides dynamic routing and allows routers to exchange information about reachable networks.

🔁 NAT / PAT

NAT/PAT provides simulated Internet access by translating private internal addresses toward the ISP-facing network.

🛡 ACL Troubleshooting

Access-control behaviour was examined as part of the troubleshooting and connectivity restoration process.

🔎 Troubleshooting Methodology

My troubleshooting workflow

  1. Identify the exact symptom.
  2. Confirm the problem using a simple connectivity test.
  3. Check the physical and interface state.
  4. Verify Layer 2 configuration such as VLANs and trunks.
  5. Verify Layer 3 configuration such as IP addresses, gateways, and routing.
  6. Check services such as DHCP, OSPF, NAT, and ACLs.
  7. Isolate the root cause.
  8. Apply the smallest appropriate correction.
  9. Re-test connectivity.
  10. Verify that the expected service has been restored.

📚 Lessons Learned

This project reinforced that network engineering is not simply about entering commands into Cisco devices.

A correctly configured network still needs to be tested, monitored, documented, and troubleshot when something changes or fails.

The most important workflow I developed through this project is: 

Observe
   ↓
Test
   ↓
Isolate
   ↓
Fix
   ↓
Verify
   ↓
Document

This approach reduces guesswork and creates a repeatable method for solving infrastructure problems.
